14  Class 14: The ID and IEN Arrays

From local basis functions to global equations

Assembly needs two pieces of bookkeeping, and they do different jobs.

IEN describes given an element and a local basis function, which global basis function is this? Given a local index \(a\) on element \(e\), it returns the global index \(A\):

\[ A = \mathrm{IEN}(a,e). \]

For a tensor-product element the local index itself comes from the stride rule of Class 11, \(a = a_\xi + (p+1)\,a_\eta\), so each element carries \(n_{en} = (p+1)^2\) of them.

ID clarifies whether this basis function has an unknown attached to it? Given a global index \(A\), it returns the equation number, or \(-1\) when the value there is prescribed:

\[ \mathrm{ID}[A] = \begin{cases} \text{equation number}, & u(A) \text{ unknown} \\ -1, & u(A) \text{ prescribed} \end{cases} \]

Equation numbers run consecutively from \(0\), skipping the prescribed nodes, so the global system is \(n_{eq} \times n_{eq}\) rather than \(n_{bf} \times n_{bf}\).

Composed, they are what the assembly loop actually uses:

\[ A = \mathrm{ID}\big[\mathrm{IEN}(a,e)\big], \]

sometimes written as its own array, \(\mathrm{LM}(a,e)\).

14.1 The mesh

Five elements: four around the boundary and one in the middle. At degree 1 the boundary edges are straight and the domain is a square with four trapezoids around a central square. At degree 2 and above the extra nodes on each boundary edge are placed on a circle, and the same five elements describe a disk.

The local origin of each element has been rotated so that they do not all start in the same corner. That is deliberate: nothing requires element 3’s local node 0 to sit where element 0’s does, and the domain boundary ends up on a different local edge in each of the four outer elements.

  • Click a node to follow it. Every element that contains it lights up, its local index is shown in each, and the matching cells in IEN and ID are highlighted.
  • Click inside an element to see all of its local indices at once.
  • Click a boundary edge to switch it between Neumann and Dirichlet. Dirichlet edges are hatched, and the ID array renumbers immediately.
IEN(a, e)  rows: local index a   columns: element e
ID[A]  top: global index A   bottom: equation number, −1 if prescribed

14.2 What the widget is showing

One global basis function, several local names. Click any node on a shared edge. It lights up in two elements, sometimes three or four at the inner corners, and the readout lists every \(\mathrm{IEN}(a,e)\) that returns it. That is the whole content of the IEN array: the same unknown is local node 6 in one element and local node 2 in its neighbour, and assembly has to add both contributions into the same global row.

The local numbering is arbitrary, the global numbering is not. Because the origins are rotated, element 1’s local node 0 is in a different physical corner from element 0’s. The mesh does not care. What matters is only that IEN is consistent with however each element chose to number itself.

Prescribed nodes drop out of the equations, not out of the mesh. Hatch an edge and watch the ID array: those nodes go to \(-1\), and every ID value after them shifts down by one, because equation numbers are consecutive over the unknowns. The node is still there, still has a basis function, still appears in IEN. It just has no equation of its own, and its known value moves to the right-hand side of its neighbours’ equations.

Two different lengths. IEN is indexed by local node and element, so it has \(n_{en} \times n_{el}\) entries no matter what the boundary conditions are. ID is indexed by global node, so it has \(n_{bf}\) entries, of which \(n_{eq}\) are equation numbers. Changing a boundary condition changes ID and leaves IEN untouched.

14.3 Things to try

  1. Click the node at the centre of a shared edge between two outer elements. It has two local names. Now click an inner corner of the middle element: three elements meet there, so it has three.
  2. Hatch one edge, then a second. Watch \(n_{eq}\) drop and the equation numbers renumber. The corner shared by the two hatched edges is prescribed once, not twice.
  3. Set all four edges to Dirichlet. Every boundary node goes to \(-1\) and only the interior nodes carry equations — at degree 1 that leaves just the four inner corners.
  4. Set every edge to Neumann. Nothing is prescribed, \(n_{eq} = n_{bf}\), and the global matrix would be singular: this is the two-prescribed-fluxes case from Project 1, Task 5, in two dimensions.
  5. Change the degree from 2 to 1. The disk becomes a square and the mid-edge nodes disappear, but the five elements and their connectivity are unchanged — degree changes the number of basis functions, not the mesh.
  6. Go to degree 3 and turn on all local indices. This is what the bookkeeping actually looks like at modest degree, and why nobody writes it out by hand.
